The host manifest permits one bounded observation attempt; it does not claim that a successful native model turn has already been qualified. Its status is `first-live-observation-required`. Root authority #4 comment 1054 already covers the constrained Attraccess workflow. ## Host-owned manifest

A trusted integrator places nonsecret qualification evidence under `ROCKY_NEXT_HOME/qualification/` and creates `authority.json` with the reviewed checks and references plus `hostAdmission` and its derived `qualification`. Setup does not create these approvals. The editable UI cannot change them.

`describeRuntime(home, authority, versions)` supplies the actual runtime descriptor without a qualification. `bindHostAdmission(descriptor, inputs)` hashes the descriptor and rendered configuration with the retained context, explicit auth-boundary decision, native artifact references, roster proof and dependency template. `qualificationForManifest(manifest)` derives the binding and ID. `buildRuntime` recomputes and verifies this binding, checks actual artifact bytes, and requires a clean packaged build. The descriptor excludes the manifest and qualification, avoiding a circular hash. Regenerate the manifest against the final Guide build before live dispatch.

The descriptor binds build/version identity, binary path/hash/size/version, model, both role prompts/steps, rendered permission/config bytes, catalog hash, canonical isolation paths, limits and evidence class. The context binds repository/task/profile, check executable/arguments, required CI names, and actual `liveApproval`, `nativeProbeEvidence`, `authBoundaryApproval` references. Referenced evidence must be regular private current-user-owned files with matching hash/size under the dedicated qualification subtree. A syntactically valid old or synthetic qualification is insufficient.

The nonsecret auth decision artifact has schema 1, `accepted: true`, the actual decision `reference`, and `boundary: "plain-0600-auth-file-bash-reachability"`. This records a user decision, not a sandbox guarantee. Auth admission uses only `lstat`/canonical-path metadata: regular 0600 file, current UID, no symlink, and owned canonical 0700 home/data/opencode parent subtree. C0, C1 and C5 recheck it; Rocky never opens, hashes, copies or proxies auth bytes. An undecided boundary refuses live preparation.

## Worker and first-live observation

The host retains its Git/GitHub/signing context. A packaged per-action Node worker starts with a real minimal environment and private HOME/TMPDIR; the adapter checks that worker's actual `process.env`. Poisoned-source rejection and the sealed native environment remain unchanged. Host staging, tree authority, coordinator application, commits and publication stay on the host. The worker has no lease acquisition/renewal, target publication or generic execution interface.

The worker shares the original host store/lease/fence. A bounded preflight → host staging → worker freeze handshake binds the full launch specification, resource/decoder/protocol limits, action and build. Host initiation and final native starts retain Store fencing. Only the host heartbeat renews the lease. Cancellation is authoritative in SQLite; IPC acknowledgement and worker exit do not establish native quiescence. Cancellation during preparation retains a proven no-dispatch settlement and releases the reserved slot. Disconnect/death stops new export/dispatch, observes supervised cleanup and retains an unresolved result without resend. The native supervisor retains command output independently of the worker.

A successful proposal must have positive native step-start/step-finish/final shapes, matching session and served identity, strict decode/EOF/exit-zero lifecycle, actual quiescence and positive nondivergent reported input+output usage. Stream/export bytes and immutable receipts must be retained. The host independently reparses those bytes, checks the durable command/receipt bindings, current binary/isolation/template and actual tree head before adopting source, committing or publishing. Reviewer admission is repeated before review-pass and human handoff. Unknown/all-zero/malformed/unresolved or retention failure cannot pass. Refusal retains original usage/quiescence; cancellation still drains the settled native action.

Full native fault/resource/lifecycle qualification, a filesystem write oracle, WAL-order guarantee, token subset semantics, effort echo and credential confinement remain disclosed/deferred. A first-live receipt closes only shapes actually observed; it does not turn an unused tool or an unobserved failure path into proof.

Terminal reconciliation authenticates and reuses the original immutable receipt before any export or receipt reconstruction. It independently rechecks native command/bundle/raw hashes, current physical quiescence, C5 identity/isolation/head and successful observation admission. A receipt retained before a crash can recover its missing SQLite projection only after those checks. Recovery rejects unknown classifications, contradictory classification/outcome pairs and incompatible usage schema or harness. It always derives usage from the bound native command and actual retained export before comparing receipt labels; an unavailable-usage label cannot skip inspection or replace measured accounting. Every claimed successful outcome passes full positive native admission. Genuine failed, cancelled and unavailable observations preserve their original usage and event. The projection is insert-if-absent/equal-or-conflict: replay cannot erase its receipt pointer, change original usage or launch another export. Corrupt, conflicting, misbound or physically unresolved replay refuses, preserves original bytes and pointers, and retains a separate durable refusal.

Each newly observed export also retains an immutable `opencode-export-observation/<native-command-id>` record through the existing Store primitive, before the final receipt and SQLite projection. It binds command/action/input/bundle, binary, exact export argv/session, environment digest, working directory, limits, raw hash/size/path and actual exit/signal/error/audit. Recovery reparses raw bytes with those independently retained completion facts. A nonzero exporter with valid JSON therefore retains unknown usage, while a receipt alone cannot invent a failed exporter to hide known counters. No new native/export process is started during recovery. Older receipts without this record are checked against the actual raw export and durable native command; recoverable measured, divergent, malformed and cancelled evidence still replays. An older exporter transport failure whose valid JSON cannot independently establish its nonzero/timeout outcome is conservatively refused without changing its evidence. This compatibility limit does not authorize a resend.
