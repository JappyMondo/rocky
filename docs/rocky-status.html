01 /

A deliberate pivot. Not two products.

The reviewer was replaced at the design/scaffold stage, not after shipping a working review product.

24-27 Aug / Original idea

A reviewer inside your PR

PR comments, learned rules, review verdicts and a multi-user web app.

28 Aug - 1 Sep / Reset

The PR became the output

The platform map replaced the old scope. Reviewer tickets were retired; the old scaffold PR was closed.

Now / Intended product

Ticket in. Approved merge out.

A daemon on your machine runs repo-owned Workflows. Review is an internal stage; you approve at a final Checkpoint.

Not "all of development" in v1: deploy/release stages, self-learning, shared hosting and Docker isolation remain out of scope. GitHub and GitLab remain required.

02 /

Real components. Missing connections.

The infrastructure exists. The user journey does not yet.

Merged and tested

  • Daemon + CLI: start, stop, status, doctor, setup and service-file generation.
  • Machine + repo plumbing: config, credentials, Repo groups, clones and worktrees.
  • Durability: Journal and replay, with two-phase Step records.
  • Integration groundwork: Linear client/webhooks, SDK contracts, Harness auth probes and CI.

Do not count as delivered

  • Agent execution: neither Harness has a runnable adapter on main.
  • Orchestration: production webhooks do not start Runs; replay has no production caller.
  • Ticket-to-merge: SCM, CI loops, Checkpoints and default Workflow content are still ahead.
  • The product UI: main has a health shell. Inbox/diff designs are throwaway prototypes.

645 tests across 44 files validate existing code, not missing features. No full real-Agent ticket-to-merge proof was found.
