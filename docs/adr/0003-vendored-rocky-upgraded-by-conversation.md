# Vendored .rocky/, upgraded by conversation

Onboarding ([NG-581](https://linear.app/digimondo/issue/NG-581)) had to choose whether the default Workflow is a file in your repo or a library import. We vendor the full default `.rocky/` into every repo — `@rocky/sdk` ships types and builders, never behaviour — because the platform's no-opt-out principle ("deleting the code that does a thing is how you stop it happening") and the runner's ignorance of product words both collapse if a library ships the default Workflow. The copy is a template with holes: byte-for-byte identical to the shipped default outside a marked Config block of consts the onboarding Agent fills, so the seed PR's diff is values, not logic, and a model never authors the pipeline a repo will run.

The price is upgrades, and we deliberately bought no machinery for them: no version marker, no three-way merge, no staleness nag. `rocky upgrade` spawns the developer's own interactive agent session with the shipped default at hand and asks it to compare and negotiate, file by file, what the human wants to take. A working `.rocky/` that is old is working; when someone wants the improvements, a conversation is more flexible than any merge algorithm against locally edited files.
