# Guaranteed Steer delivery instead of a Workflow-drained Interruption queue

[Run lifecycle](https://linear.app/digimondo/issue/NG-574) originally shipped `ctx.interruptions()`: a journaled Step returning the human remarks queued since the last call, with the Workflow deciding who reads them. That put the platform's own principle — content decides, the runner never interprets — in charge of delivery, and it opened a hole: a Workflow that never calls it silently swallows the human's words.

[Steering and Interruptions from Linear mid-Run](https://linear.app/digimondo/issue/NG-584) closed the hole by inverting the design: **every prompt typed at a working Run is a Steer, and the runner guarantees its delivery.** A Steer lands in the active Agent conversation at the next turn boundary (Rocky never cuts a turn short for one); a Steer that finds no conversation — `exec`, `ctx.step`, a Run parked on CI, the gap between Steps — waits as a pending Steer and lands in the next conversation that opens, at its first turn boundary, via the same interrupt-and-resume mechanic. One delivery mechanism everywhere, including into the cold re-run after a crash, so a crash costs the conversation but never the words. `ctx.interruptions()` is **deleted**; a Checkpoint reached while notes are still pending surfaces them in its body.

The trade-off is deliberate: we gave up the Workflow's ability to route notes to a chosen Step (Run lifecycle's `humanNotes`-into-the-fixer pattern) in exchange for the delegate promise that talking to a Run always works. A note may land in a schema-bound Agent that cannot act on it — the same cost the mid-Step premise already accepted. This does not breach the runner-never-interprets principle: the runner delivers words verbatim and attaches no meaning; only *whether* words arrive stopped being content's job. It also deletes a `ctx` member rather than adding machinery (`ctx` returns to nine members plus the non-journaled `stage()`).

**Amendment (2026-09-02) — the two attempt kinds this pins.** Inverting the design left the resulting attempt unnamed, and the sources that did name it disagreed, so: a Step's `attempts[]` (Run lifecycle §6) is discriminated by exactly two `kind` values, **`failed`** and **`steer`**, over a common `{ startedAt, ms, sessionId? }` — `failed` carries the `error`, `steer` carries the `note`, and only the successful attempt sets the entry's `result`. **`interrupted` is not a stored attempt value.** NG-574 §7 step 3 wrote the steer attempt as `{ kind: "interrupted", note }`, but §7 describes a single event — stop the harness at a turn boundary, record the attempt, resume the same session with the note verbatim — and a single event is a single attempt; splitting it into `interrupted` plus `steer` would persist the mechanism and the intent as two entries for one occurrence, and would bake into the format the very word `CONTEXT.md`'s **Steer** term tells everyone to avoid. What is untouched is the *Step*-level sense of the word: §5's "a seq whose last line is `running` is **interrupted**" names a torn two-phase write, an entirely different thing from a Steer, and keeps its name. Only the attempt kind is affected. [Journal and replay](https://linear.app/digimondo/issue/NG-596) implements the union.
