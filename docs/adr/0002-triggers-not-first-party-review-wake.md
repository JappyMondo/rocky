# Triggers instead of a first-party review-wake

The map originally had human PR review comments waking a parked Run back into the fixer loop. Designing that wake ([NG-580](https://linear.app/digimondo/issue/NG-580)) meant real framework surface: a daemon-side poller for every parked Run's PRs, and a `ctx.checkpoint()` that can return "the world changed under me" instead of an Answer — a race primitive the Journal has no spelling for.

We rejected it in favour of **Triggers**: `workflow.ts` default-exports a table of bindings built from SDK builders (`linear.onDelegate(fn)`, `manual(name, fn)` in v1), and "address PR conversations" is just a second Workflow bound to a manual Trigger that a human fires from the web UI or CLI when they see review comments. Rocky never watches PR reviews at all. This trades away automation (a human must notice the review and fire the Trigger) for exactly the building-blocks bet the platform is built on: connecting a Workflow to Linear is content, not a privileged runner behaviour, and a third trigger kind must be addable as a builder without touching the runner. Consequences: the daemon resolves a Trigger by importing `workflow.ts` outside any Run — a conscious softening of the only-`mcp.json`-is-read-outside-a-Run principle — and follow-up Workflows need no hand-over state, because a Run adopts whatever the issue's branch already holds.
